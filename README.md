## About Me

I am Ilham Amjad, a full stack developer working primarily in the MERN stack — MongoDB, Express, React and Node — with React.js as my area of depth. I work across the whole request path: the interface someone touches, the API that serves it, and the schema underneath that has to hold up under real usage. I am based in Pakistan and work with clients and teams remotely.

My work leans toward products that need to look finished and behave predictably: dashboards, authenticated applications, and marketing or landing surfaces that convert. I care about the parts of an application that are invisible when done well — loading states, error boundaries, token expiry, query performance — because those are what separate a demo from something a business can run on.

## Developer Philosophy

**Software should feel considered, not assembled.** A few things guide how I build:

- **Interfaces are contracts.** If a button says "Save changes," the result should say "Saved" — not a generic success toast. Naming stays consistent from the trigger to the outcome.
- **The backend is not an afterthought to the UI.** Validation, authentication and error handling get designed before the first screen is styled, not patched in once the frontend "works."
- **Boring is a compliment.** Predictable state management, typed contracts between client and server, and consistent naming conventions matter more to me than clever one-off solutions.
- **Performance is a feature, not a cleanup task.** Bundle size, query shape and re-render cost are considered while building, not fixed in a later pass.

## Development Workflow

1. **Scope** — define the data model and API contract before writing a single component.
2. **Build the API first** — routes, validation and auth middleware, tested with Postman against real request shapes.
3. **Build the interface against the real contract** — no mocked data left behind in production code.
4. **Review for edge cases** — empty states, failed requests, slow networks, expired sessions.
5. **Optimize** — bundle size, query cost, re-renders, only once correctness is settled.

### Architecture Principles

- Keep business logic out of components; components render state, they do not compute it.
- One source of truth for server state (Redux Toolkit Query or equivalent), one for local UI state.
- Every API route validates its input and returns a consistent error shape — no silent failures.
- Authentication is handled once, centrally, and reused — never re-implemented per route.
